# LanChat

Go 编写的局域网消息与文件分享工具。无中心服务器，前端随可执行文件打包，支持 macOS、Linux、Windows；手机通过浏览器连接电脑节点。

## 构建和测试

项目没有 Go 模块外部依赖。conda 用于提供 Go 工具链，应用运行时不需要 conda。

```sh
source /opt/anaconda3/etc/profile.d/conda.sh
conda activate /Volumes/T9/test/envs/monitor
make test
make build
./lanchat
```

其他机器只需将 Go 加入 PATH，或使用 `make GO=/path/to/go build`。建议使用受维护的 Go 1.26 / 1.27 工具链。`make build-all` 交叉编译以下五种目标：darwin/arm64、darwin/amd64、linux/arm64、linux/amd64、windows/amd64。

GitHub Actions 在 Windows、macOS、Linux 上分别运行 Go 1.26 / 1.27 的 `go vet`、带竞态检测的单元及 HTTPS 集成测试、前端回归测试。全部测试通过后打包五种目标，上传包含二进制、本文档、SHA-256 校验值的 tar.gz 文件（Actions 页面 Artifacts，保存 14 天）。Windows 可用系统 tar 或解压工具打开。该流程不自动发布 Release，也不提供代码签名或 macOS 公证。

## 连接设备

启动后会显示两个入口：

- **本机管理界面**：随机端口的 `http://127.0.0.1:...`，只监听回环地址，可管理配对、发布本机路径、撤销手机授权。
- **局域网 HTTPS 入口**：默认端口 52520，用于电脑配对、消息、文件和手机访问，最低 TLS 1.3。

### 电脑配对

从目标电脑界面复制完整配对串：

```text
IP:Port#6位配对码@64位设备公钥SHA256指纹
```

在另一台电脑的“添加电脑”中粘贴。指纹需要通过你信任的渠道获取；不要使用陌生人提供的配对串。客户端将目标 TLS 证书公钥与完整指纹比对，然后才发送配对码和共享密钥。发起方使用 Ed25519 签名证明设备身份，后续请求使用绑定方法、路径、正文、时间及 nonce 的 HMAC，并拒绝重复 nonce。

配对码有效期 3 分钟，成功后失效；界面刷新配对信息可获得新码。目标节点每分钟最多接受 10 次配对尝试，最多信任 64 台设备。公开 UDP 扫描只帮助定位地址，不能证明设备身份，仍需复制完整配对串。

**与旧版不兼容**：旧版纯 HTTP 节点及只有 `IP:Port#PIN` 的配对串不能连接。请同时升级所有节点；旧密钥曾通过明文配对交换，升级后建议在双方移除旧配对并重新配对。

### 手机连接

电脑点击“手机扫码”，手机访问 HTTPS 链接。设备使用自签名证书，浏览器首次会提示证书不受系统信任；请先在可信网络中核对电脑设备身份，再信任该证书。电脑间自动指纹校验不等于手机浏览器已完成身份校验。更严格的部署应由管理员将核验后的设备证书配置到手机信任库，避免盲目信任证书提示。

扫码令牌位于 URL fragment，页面先清除 fragment，再通过 POST 换取 Secure、HttpOnly、SameSite=Strict Cookie。令牌按小时轮换，最多有效 8 小时；电脑可以撤销所有手机令牌，手机需重新扫码。手机可收发消息和文件、清空本机消息，不能管理配对、读取配对码、发布电脑文件路径或清空其他节点。

页面静态资源可公开加载，消息和文件 API 需要授权。添加到主屏幕的能力取决于浏览器，不提供离线聊天或完整离线 PWA。

## 消息与文件行为

- 消息只保存在进程内存中，默认最多 200 条、20 MiB **估算存储预算**，按 FIFO 淘汰。这不是整个进程或浏览器的 RSS 上限；网络、JSON、TLS、快照和 Go 运行时另有内存开销。
- 前端同步淘汰消息，保留的卡片增量更新；公共频道和定向私发分别显示。
- 发送使用 4 个工作协程和有界队列。每个目标最多尝试 3 次，显示发送中、已送达或失败；支持手动重试，检测到离线设备重新上线后也会补发仍留在内存中的失败消息。送达指目标节点已接收，不代表对方已阅读。被淘汰、清空或进程退出的消息不会补发。
- 广播只发给本机直接配对的设备，不跨第三台节点转发。全端清空只尝试通知已配对的可达设备，不能保证清除离线节点、已下载内容、截图或系统缓存。
- 浏览器上传通过 64 KiB 缓冲写入**本机磁盘临时目录**，完整接收并计算 SHA-256 后发布卡片。接收者再下载；这不是上传与接收同步的中继。默认每次请求总文件字节不超过 1 GiB、每个进程会话临时目录不超过 2 GiB，单次最多 64 个文件，上传经过有界准入并串行分配磁盘空间。
- 本机路径分享不预先复制文件。下载直接读取原路径，原文件必须保持可读且内容不变；本机路径分享不会预先计算整文件哈希。只接受普通文件。
- 下载支持 Range，远端文件经本机 HTTPS 代理，私发文件仅允许目标配对节点读取。上传文件的 SHA-256 作为元数据及下载响应头提供，浏览器下载不自动进行整文件哈希验证。
- 正常退出、消息淘汰或清空会删除相应临时文件。崩溃或强杀可能留下文件；下次启动清理同一配置目录下超过 24 小时未更新心跳的会话目录。未到清理期限的旧会话仍占磁盘；配额是当前会话配额，不是整个磁盘配额。删除不是安全擦除，程序也不承诺内存取证级销毁。

## 参数

```sh
./lanchat --daemon                 # 前台无界面运行；不是系统服务安装器
./lanchat --no-open                # 不自动打开浏览器
./lanchat --tray                   # 打开浏览器并尝试桌面通知；不是原生托盘
./lanchat --name My-PC --port 52520 --udp-port 52525
./lanchat --max-mem 20 --max-msgs 200 --max-upload 1024 --max-spool 2048
./lanchat --config-dir /path/to/private-config
```

容量参数以 MiB 为单位，`max-spool` 不得小于 `max-upload`。首选端口被占用时自动选取可用端口，以终端显示为准。多网卡设备可以在手机二维码对话框选择 IP；电脑配对时可将完整串中的 IP 换成目标设备可达的地址，保留 PIN 和指纹。

## 信任边界

“默认隐身”指默认不响应公开 UDP 发现，不代表网络端口无法扫描。已有配对设备离线时会通过经过 HMAC 认证的 UDP 广播探测地址，流量依旧可以被观察。

本机进程和能够直接访问回环接口的本机用户视为管理员。手机共享宿主节点的消息视图，不是独立设备身份。可信电脑能够发送公共消息和清空请求，请只配对你管理的设备。配置目录包含设备私钥和共享密钥，以用户私有权限保存，备份也应受到保护；配置损坏时启动报错，不会静默覆盖原身份。

服务拒绝未知 Host、跨站 Origin、远端明文访问与主动内容类型的图片。WebSocket 限制连接数、帧大小和慢客户端队列，并定期 Ping/检查手机授权。仍建议只部署在受控局域网，不直接暴露公网。
